闭环 · 任务的灵魂

先回一行字，再决定今天

每天刷新时，必须先回采昨天的完成度与个人感受，再据此决定今天加量、减量或改动作。没有身体反馈时不许加量 —— 这是 6.3 节的关键约束。

01唯一真实通路

有效

用户在对话里回一行文字

Agent 解析 → 写入 回采记录.md 台账 → 次日据此调整课表。

Agent 读不到浏览器 localStorage：HTML 卡片里的勾选框只存在用户本机浏览器里。

因此

回采提问必须同时出现在对话正文和海报底部，不能只放交互页面。

试过但无效

三种增加摩擦的方案

  • 一键四档回采按钮
  • 自动复制回采码到剪贴板
  • 回采码导入导出

根因：用户在手机微信读回复，本地 HTML 根本没被打开过。

一句话教训

任何改动若增加回采摩擦，都会让闭环断掉。

02固定双行提问

一次只问最少的字，并给一个可直接抄改的例句。

昨天：完成度 / 一个针对性体感
今天：完成度 / RPE / 哪里酸
例：昨天 100 / 臀有感 · 今天 80 / 6 / 肩前侧

周日 / 周一额外追缴

体重 / 腰围 / 后脑离墙。周日是每周结算点，每 4 周还要同条件复测。

针对性体感按课型轮换

后链日臀能不能找到发力
下肢力线日膝内侧晃不晃
上肢推日肩前侧夹不夹
上肢拉日哪里酸
循环日哪里最喘

这些体感同时是 6.3 节的降级触发信号：一旦上报酸痛 / 膝内侧晃 / 肩前侧夹挤，对应动作立即降级或替换，不硬扛。

03数据格式与台账

两种结构化码

CK1|日期|完成度|RPE|精力|酸痛|感受 MS1|日期|体重|腰围|后脑离墙

自由文本优先接受，哪怕只有「练了」两个字 —— 先记完成度，细节后补。

台账表头

日期 | 课型 | 完成度 | RPE | 精力 | 酸痛 | 感受

用户回复后，解析结果追加到 回采记录.md；若 今日训练卡.html 存在，同步写进它的 ARCHIVE 常量。

台账另设「累计观察」，每日记录零回采天数与版本判断。

04调整决策规则（6.3）

判断理由必须写在海报顶部提示条里。

有回复

  • 哪怕只两字 → 优先抓完成度 + 当课型的针对性体感（膝内侧 / 左臀 / 肩前侧），再谈加量。
  • 完成度 100% 且 RPE ≤ 6 且连续达标 → 才按 4.3 进加量台阶。
  • 上报酸痛 / 膝内侧晃 / 肩前侧夹挤 → 对应动作降级或替换，不硬扛。
  • 出现麻木 / 放射痛 → 停训就医，写进当日海报红线。

无回复

  • 累计零回采天数 +1；顶部写明「N 天没有回采，不加组、不加重量、不补课」。
  • 连续 ≥ 3 天 → 本周加量条降级为「回归版 · 本周先不加量」，不补偿、不补课。
  • 连续 ≥ 5 天 → 明确写「上周整周没有回采 · 不补课不补偿」。
  • 结算点（周日 / 第 4 周）无数据 → 不进加量台阶，维持第 1 周标准版，并追缴三个数字。

决策链

刷新 · 读台账→ 昨天有回采？→ 无 → 零回采 +1 · 回归版→ 有 → 看酸痛 / 完成度 / RPE→ 定执行版本→ 理由写进提示条

三种执行版本

标准版（第 1 周容量）｜回归版（无反馈，维持标准版、不加量）｜加量版（仅在 100% + RPE≤6 + 连续达标后出现）。减量周是计划内 −40% 容量，与这三者不冲突，需要在提示条里单独说明。

05每日运行 SOP

读历史 → 算课次 → 回采昨天 → 依反馈调整今天 → 出海报 → 更新台账 → 交付。

Step 0 · 读历史（必做）

移植包 + 回采台账 + 自动化记忆 + 最近一次交付物；确认昨天有没有运行记录、有没有回采数据、当前连续零回采天数、本周是否该进加量台阶。

Step 1 · 算今天

按 4.1 算周次 / 本周第几天 / 星期 → 取 4.2 对应课次；写明「第 N 周第 D 天 · 分期 · 标准版 / 加量版 / 回归版」。

Step 2 · 回采昨天（灵魂，不能省）

在对话正文里直接问，别指望用户去打开 HTML 点按钮；固定双行格式 + 例句；周日 / 周一额外追缴三个数字。

Step 3 · 依反馈调整今天

解析 CK1 或自由文本并追加台账；按 6.3 定执行版本，把判断理由写在海报顶部提示条；无回复则零回采 +1。

Step 4 · 生成今日海报（主交付物）

写 poster-MMDD.html → 渲染 poster_MMDD.png。PNG 是主交付物：手机微信里本地 HTML 打不开，图片能直接看、能点开放大。

Step 5 · 检查再交付

截图后分段检查顶部与底部文字是否截断 / 重叠；用 present_files 交付 PNG + HTML 源文件；对话正文按第 3 节偏好写 5–8 条要点 + 回采提问。

Step 6 · 收尾

追加台账「累计观察」、写当日工作日志、写自动化记忆（只写摘要与判断，不放海报全文）。

06移动端输出偏好（强约束）

用户在手机微信上读回复，按移动端排版，不假设宽屏。

不要宽表格

超过 3 列就拆成列表。

每行短

一行一个信息点，不堆长句和数字串。

结论前置

第一屏先给「今天练什么 / 有没有加量 / 需要你回什么」。

重要数字单独成行 + 加粗

金额 / 数值保留两位小数即可。

少用标题层级

用空行 + 加粗分段。

正文只留 5–8 条要点

长明细放进文件给路径；语气直接，不客套。
