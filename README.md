# 体态矫正 12 周训练计划

把《锻炼计划-定时任务移植包.md》整理成可直接发布的静态站点：完整保留计划中的主题、目标、步骤、重点信息与关键术语，按信息层级组织，并补充概括与可视化呈现。所有内容均以该文档及工作区回采台账为事实来源，**不引入计划外的判断或数据**。

- 评估日：2026-10-19
- 计划起点：2026-10-19（第 1 周第 1 天，周一）
- 站点内容快照：截至 2026-11-10 的台账状态（连续零回采 22 天）

## 页面结构

| 页面 | 内容 |
| --- | --- |
| `index.html` | 总览：需求与 4 条硬要求、12 周目标、三个分期、干预优先级、一周编排、每日闭环、关键术语、安全红线 |
| `baseline.html` | 基线评估：BIA 身体成分、围度、自上而下的体态问题、力线传导、干预优先级、安全红线、12 周目标 |
| `schedule.html` | 完整 7 天课表：松解 / 激活 / 主训练 / 收尾四阶段逐项组次与要点、周二的「没器械」替代、日常习惯 6 条 |
| `progression.html` | 12 周进阶：周次计算、12 周地图、渐进超负荷规则、分期目标、营养框架、每 4 周复测 |
| `feedback.html` | 回采闭环：唯一真实通路、双行提问、CK1 / MS1 格式、6.3 决策规则、每日 SOP、移动端偏好、已知状态、验收清单 |
| `posters.html` | 每日海报：为什么用 PNG、9 个区块顺序、视觉规范与主题色轮转、HTML→长图流程、3 张已交付样例、定时任务配置 |

## 本地预览

纯静态，无构建步骤、无外部依赖。任选其一：

```bash
# Python 3（在本目录执行）
python -m http.server 8080

# 或直接用浏览器打开 index.html
```

桌面与移动端均已适配：顶部导航在窄屏折叠为菜单，页面内提供锚点目录；所有数据以卡片 / 键值列表呈现，不使用超过 3 列的宽表格。

## 发布

仓库推送到 `main` 分支后，`.github/workflows/pages.yml` 会借助 `actions/configure-pages@v5` 的 `enablement: true` 在首次运行时启用 GitHub Pages，并把仓库根目录作为静态产物部署。

发布地址：`https://sxs159733.github.io/posture-correction-plan/`

## 事实来源与边界

- 唯一事实来源：工作区根目录《锻炼计划-定时任务移植包.md》；台账状态参考《回采记录.md》。
- 身体数据来自 BIA 体测与教练站立位目视筛查，**属初步筛查，不是医学诊断**。侧弯与 O 型腿需先经康复科 / 骨科确诊。
- 站点只呈现计划内容与训练安排，不替代临床评估；不引入计划外的训练动作、数值或结论。
- `posters/` 中的三张海报是每日自动化实际交付的 HTML 源文件，作为样例原样保留；「每日海报」页用 iframe 等比缩放实时预览它们。同一份 HTML 在每日自动化中还会被渲染成 860px 竖版 PNG，PNG 是手机微信端的主交付物，属于二进制产物，不纳入本静态站点仓库。
- 仓库内全部文件均为文本，无二进制、无外部 CDN 依赖，GitHub Pages 可直接托管。
